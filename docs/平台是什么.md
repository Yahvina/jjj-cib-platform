# 平台是什么

> 面向：接手本仓库的人、写软著／专利／论文的人、需要向导师或合作方解释平台的人。
> 对应源码版本：`platform/v1.5/`（原型 v1.5，2026-10-26 时点）。
> 本文只讲「为什么这么做」，字段与函数的实现细节见 `docs/技术文档_v1.5.html`。

---

## 一、一句话定位

平台的算法说明页第一句就是标准答案：

> 交叉影响平衡（Cross-Impact Balance，CIB）不预测未来，也不计算减排量。它只回答一个问题：**这一组政策摆在一起，是否互相抵消。**

换句话说：**它是下游模型（GCAM-China / CHEER-CGE）的上游安检机，不是模型的替代品。**

下游模型能算出「碳税 200 元、风光装机 12 亿千瓦，2035 年京津冀排放是多少」，但它**不会质疑前提**。你同时设定「加速服务化」和「高耗能产业保持规模」，模型照样给你一个数——而那个数建立在一组自相矛盾的假设上，是废的。平台就是用来在花几十小时跑模型之前，先把这类自相矛盾筛掉的。

边界必须说清：

| 适合 | 不适合 |
|---|---|
| 情景设定的前期论证 | 评估政策效果 |
| 跨层假设的一致性检查 | 给出减排路径或幅度 |
| 为下游模型准备输入 | 预测经济增速、人口规模 |

## 二、为什么需要「描述符」

**描述符是政策语言与模型语言之间的翻译中介。**

政策是中文，模型只认参数。「严格控制新建煤电项目」这句话，GCAM 要的是 `Capacity|Electricity|Coal` 在某年的取值。中间隔着一道鸿沟。如果让每个人自己从政策跳到参数，那就是纯拍脑袋，也无法比较。

描述符在这道鸿沟上架了中间层：

```
政策条款（中文）  →  描述符（19 个）  →  模型参数
「钢铁产能置换」     「钢铁工艺路线」      Production|Iron and Steel|Steel
                     选：短流程与氢冶金为主  → 技术份额权重
```

这一层承担三件事：

1. **可比**——无论从哪份政策文件出发，都归到同一组 19 个描述符，政策之间才能放在一张表上比。
2. **可判**——打分与一致性检验需要能离散成有限选项的对象，政策条款不能离散，描述符可以。
3. **可换**——描述符框架自 v1.3 起可整体替换（见「框架通用化」）。换领域只换这一层，下面的打分、检验、导出的代码不动。这是软著的技术卖点。

### 19 个描述符按类型分三种

| 类型 | 数量 | 含义 | 进模型的姿势 |
|---|---|---|---|
| 输入型 | 4 | 外部给定，模型改变不了 | 直接给定序列 |
| 参数型 | 13 | 模型吃系数／份额，政策改的是这个 | **需要翻译** |
| 结果型 | 2 | 模型算出来的，只能「期待」 | 只作输出对照，不设值 |

三级组织（六个一级类）：经济与人口、能源系统、产业与技术、终端部门、资源与环境、政策与治理。

**参数型那 13 个才是「政策→模型」真正要动手的地方**，也是本项目的学术重点。

## 三、为什么要「选择状态」

政策不说「服务业占比等于 73.2%」，政策说「加速服务化」。**状态就是政策的档位语言。**

19 个描述符合计 55 个状态。每个描述符的状态列表**按强度从高到低排列**（这一条很重要，见第七节）：

```
经济增长速度：  高速 ／ 中速 ／ 低速
产业结构：      加速服务化 ／ 稳步演进 ／ 转型滞后
钢铁工艺路线：  短流程与氢冶金为主 ／ 长流程为主      （只有 2 档）
```

每个状态还挂着三样东西：

- **翻译说明**——「你说的是服务业占比到 75%，模型不吃占比，它算的是收入弹性。翻译动作是把占比目标反推成弹性系数。」
- **2030 / 2035 锚定依据**——政策目标或现状起点，能查证。
- **取值区间**——进入导出环节的数值上下界与单位。

### 勾选＝划范围，不是挑一套情景

状态面板是**多选**的。勾选的档位构成该描述符的「可信范围」：

- 勾一档 ＝ 主张「就是这个」；
- 勾多档 ＝ 主张「在这个区间内」；
- **一个都不勾 ＝ 不设限**，全部档位参与。

一致性检验只在这个范围内枚举。范围越窄主张越具体，也越容易找不到自洽情景。

只有**当每个描述符都恰好勾了一档**时，才存在唯一的一套情景，平台才会判「你选的这套站不站得住」（`checkSelected`）。否则报的是「这个范围里有多少种组合最终自洽」。

## 四、为什么要「打分」——打分打的是什么

这是最容易误解的一步。**第 5 步打的不是「这个政策好不好」，而是「描述符 A 的状态变了，会让描述符 B 往哪边走、强多少」。**

### 记录单位是「描述符对」，不是「状态对」

打分矩阵是 19×19 去掉对角线 ＝ **342 格**。每格一个分值 `v ∈ {−3…+3}`，外加置信度（高／中／低）、依据文字、是否复核。0 与「未判」是两回事：0 表示「两者之间没有直接关系」，可以判得很有把握。

为什么不在状态对上打分？19 个描述符的**有序状态对共 2864 格，是描述符对的 8.4 倍**，人工打不完。

### 状态对的值从哪来：默认展开

枚举判定（`evalCombo`）需要的是**状态级**影响值。平台用一条线性斜坡把描述符对的分值展开到状态对（`expandV`）：

```
影响值 = v × (2·pa − 1) × (2·pb − 1)
pa = 来源描述符的位置系数 = (n−1−fi)/(n−1)
pb = 目标描述符的位置系数 = (m−1−ti)/(m−1)
```

3 档描述符的位置系数分别是：**首档 +1、中档 0、末档 −1**。

也就是说，默认展开隐含两条假设：
1. **状态列表按强度从高到低排列**——首档是「强」，末档是「弱」；
2. **整体倾向 `v` 的语义是「来源取首档、目标取首档时的影响」**，其余位置按系数缩放。

人工可以在**状态级精判**表里逐格覆盖（`st` 字段），覆盖值优先于展开值。报告会披露有多少格被精判过。

### 打分有什么用：算「影响平衡值」，定义「自洽」

对某个描述符的某个状态，把它从**其余所有描述符**那里承受的影响加起来，得到**影响平衡值**。

> **自洽判据**：一个情景是自洽的，当且仅当**每个描述符的选定状态，都是它自身影响平衡值中得分最高的那一项**。

平台枚举范围内的全部组合（完整空间是 3¹⁷×2² = 516,560,652，超过 25 万即启用固定种子抽样，报出的自洽数是**下限**），逐组判定，保留自洽的。

**没有打分，「自洽」这个词就没有定义。** 打分是把「这几个政策会不会打架」这个模糊判断变成可计算量的那一步——这就是 CIB 方法学的内核。

### 跨层：约束前置

相邻层级之间按取值区间核对：上级某档与下级某档区间完全不相交时，下级该档不进枚举。第 3 步选定上级档位后立刻筛下级可选状态，不必等跑完再回头发现问题。逐层求解的内核（`solveLayer` / `allowUnder` / `runLayered`）在结构收敛中保留。

## 五、导出的「配置文件」里到底是什么

「生成结果」有**四种形态**，因为下游要的东西不同：

| 形态 | 产出 | 给谁用 |
|---|---|---|
| 模型配置文件 | GCAM 的 `configuration.xml` 片段／GAMS 的 CSV→GDX | 直接挂进模型 |
| 结构化参数表 | `param,value` 的 CSV | 人看、录 Excel |
| 定性叙事 | 文字稿（显式声明「不含模型可读的数值参数」） | 写报告／PPT |
| 贝叶斯概率分布 | 后验均值、sd、5%/95% 区间、P(升高/维持/降低) | 做概率情景 |

### 模型配置文件（默认形态）

GCAM 路线生成一段可塞进 `configuration.xml` 的 `<ScenarioComponents>`：

```xml
<!-- 平台自动生成 · 写入 configuration.xml 的 ScenarioComponents -->
<!-- 取档方式：区间中点；年份锚点 2035；参数值见同目录的参数表 CSV -->
<!-- 产业结构 → Value Added|Industry = 待人工给值；… -->
<ScenarioComponents>
  <Value name="...">某个 xml 文件名</Value>
  ...
</ScenarioComponents>
<!-- 以下 N 个描述符平台无法确定装配文件，需人工补齐：… -->
```

最后那行注释是**刻意的诚实设计**：平台不知道装配文件时明确标出来，不静默兜底成碳价文件。

GAMS 路线输出 CSV，注释里写明「之后由 GDXXRW.EXE 转为 GDX」。
表头 `param,scenario,value,unit,low,high,state,scope,year,note`。

### 参数表（字段最全的一种）

表头 `descriptor,param,scope,year,value,low,high,unit,state,evidence,note`，逐字段含义：

| 字段 | 含义 |
|---|---|
| `descriptor` | 描述符名（人可读） |
| `param` | 模型变量名（如 `Value Added|Industry`） |
| `scope` | 适用地区（北京／天津／河北／区域） |
| `year` | 年份锚点（2035；2025／2030 需按政策里程碑插值） |
| `value` | 按选定状态与取档方式（下界／中点／上界）换算出的数 |
| `low` / `high` | 状态的取值区间 |
| `unit` | 单位 |
| `state` | 原始状态名（保留人可读的选择） |
| `evidence` | 依据 |
| `note` | 装配说明；给不出值时写「该状态未定义数值区间，需人工给值」 |

多档勾选（＝划范围）时，单情景导出按**每档的第一档**取值，并在文件头用注释提醒改用「导出全部自洽情景」。

### 所以配置文件的定位

**一份「待核对的草稿」，不是「可直接跑的结果」。** 它完成机械部分：变量名对齐、按档位取值、区间换算、装配清单。剩下需要经验或平台无从判断的部分（确切的 xml 文件名、部分系数）明确标给人。这是它与「一键出结果」类工具的根本区别。

## 六、政策库与数据集侧的分工

平台内置 **106 条政策路径**（89 条 CCPID 国家库 ＋ 17 条京津冀地方补充），每条路径可映射到零个或多个描述符。

**映射为 0 不是缺陷**，而是一条结论：这条工具不落在当前模型的变量口径内——模型看不见某些政策。

分工界线（不得混淆）：

| | 负责 | 内容 |
|---|---|---|
| 数据集侧 | 同学 | 政策事实采集、编码、核验、政策库维护、评分依据换源 |
| 模型侧 | 本项目 | 描述符构建、参数翻译、一致性检验、平台开发 |

数据集侧的产出是**依据库**（政策文件主记录 ＋ 条款 ＋ 模型映射字段：目标年份、对应描述符、模拟方法、对应参数、参数值、换算依据），为本平台提供「描述符→参数值」的最后一段与可追溯的政策出处。平台的 `why` / `evidence` 字段是对接点。

## 七、已知边界与坑

写在这里是为了不让接手的人重复踩。

### 1. 中档在默认展开下「因果惰性」（重要）

由 `expandV` 的系数表可得：**某个描述符位于中档（索引 1）时，它对其他所有描述符、所有目标档位的影响恒为 0**（首档 +1、中档 0、末档 −1）。

推论：**若一个情景中所有描述符都在中档，它的自洽判定与打分完全无关。** 实测：17 个三状态描述符全取中档，200 次随机打分全部判为自洽。而「全取目标节奏／现行标准」恰恰是最保守、最可能被当基线用的情景。

实测数据：

| 场景 | 全中档情景判为自洽 |
|---|---|
| 17 个三状态描述符全取中档 | 200/200（与分值无关） |
| 任意 5 个三状态描述符全取中档 | 200/200（与分值无关） |
| 真实 19 个描述符（含 2 个两状态） | 0/200（被两个两状态描述符打破） |

影响值实测：源中档→目标高档 ＝ 0；源高档→目标中档 ＝ 0；源中档→目标低档 ＝ 0；源高档→目标高档 ＝ `v`。

同时，**界面在打分处没有告诉使用者「状态列表按高→低排列、中档系数为 0」**，只有报告末尾的「边界说明」提到未精判的按两端状态高低位置展开。状态级精判表可以逐格覆盖，但那是 2864 格。

> 当前无测试覆盖 `expandV` 与中档行为。

### 2. 两个描述符只有两档

`钢铁工艺路线`（短流程与氢冶金为主／长流程为主）与 `碳移除规模`（含工程化移除／仅生态碳汇）没有中档，位置系数只有 ±1。涉及「中档」的讨论对它们不成立。

### 3. 抽样是下限

组合空间超过 25 万时按固定种子抽样，报出的自洽组合数是**下限**，可能把「没抽到」误判成「不可能」。档位对数量多时应以方向为准。

### 4. 政策路径数与条款数不是同一口径

平台说「106 条政策路径」＝政策工具×描述符的配对数；数据集侧说「58 条原句」＝条款数。对外表述不要混。

### 5. 版本号三处绑定

`merge_v15.py` 的 `VER`、成品文件名、`index.html` 的 `<title>` 必须一致，改版本要一起改。

## 八、对外怎么讲（PPT 开场两页）

导师在 2026-10-26 面谈里用的比喻可以直接用，他认这个说法：

> **CIB 是发动机，不是驾驶舱。**
> 现在这台机器把发动机摆在最外面：七步流程、19 个描述符、55 个状态、5 亿组合、影响平衡值——这些是我的工作语言，不是政策研究人员的语言。
> 政策研究人员关心的是「交通部门怎么脱碳、建筑部门怎么脱碳、这些政策之间怎么排布」。所以下一步要做的是给发动机装上驾驶舱：按部门组织入口，每项政策是「实施年份 ＋ 执行率／强度」，一致性检验退到后台当内核。

第二页讲边界，一句话：

> 这个工具不预测排放、不算减排量。它只回答一件事：把这组政策摆在一起，它们互相抵消吗。效果由下游模型算，前提由这个平台保。

## 九、一页速查

| 步骤 | 做什么 | 为什么必须有 |
|---|---|---|
| 1 选择尺度 | 勾选本次覆盖的层级 | 国家目标是外部条件，不能与自己设的变量混在一起 |
| 2 政策库与映射 | 把政策工具挂到描述符 | 让每个选择都有政策出处 |
| 3 描述符与状态 | 给每个描述符勾选可信档位 | 政策语言 → 可计算的离散量 |
| 4 校验方式 | 定专家判断人数、是否叠加贝叶斯 | 影响矩阵的可靠性取决于判断来源 |
| 5 交叉影响打分 | 342 格描述符对判断 | **定义「自洽」**，没它后面全是空的 |
| 6 目标模型 | 选 GCAM-China / CHEER-CGE | 决定导出成 xml 还是 CSV |
| 7 检验与导出 | 枚举 → 筛自洽 → 出配置 | 交付一份逻辑上站得住的政策包 |

平台不预测未来。它保证你送进模型的那套政策包，自己在逻辑上立得住。
